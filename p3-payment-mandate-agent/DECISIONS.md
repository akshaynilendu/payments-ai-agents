# Decisions (Project 3: Payment Mandate Agent)
D1 Scope (v1): a small business's finance agent doing refunds and supplier transfers on UK FPS and SEPA Instant under one standing mandate. Outcomes: PAY, REFUND, ASK_HUMAN, DECLINE. Made-up data only.
D2 Code decides, the agent proposes. All checks live in the MCP server (the bank side); no prompt is a control. Reason: AP2 security considerations treat prompt injection as infeasible to prevent fully.
D3 Versions A (code), B (single agent via MCP), C (agent, server checks off, test data only), D (orchestrator + two specialists via MCP). Ship rule: simplest version that passes the hard gate (zero money outside the mandate) with the best score.
D4 Two tool sets. The agent gets 5 tools over MCP: get_mandate, lookup_order, lookup_supplier, check_payee (read only) and propose_payment (the only one that can lead to money moving, and only if the engine says yes). The owner tools (approve_payment with passkey, revoke_mandate, pause_all, export_evidence_pack) are never exposed to the agent: the kill switch belongs to the owner, not the thing it stops. The server sets the request id itself, so an agent can't act on another request.
D5 One proposal per request. The idempotency key is the request id: a second proposal with different details is refused (IDEMPOTENCY_CONFLICT), so an agent can't keep retrying until something passes.
D6 Version A (code only) baseline, run 25 Oct: 29/40 right, 7/7 textbook, 0/5 variants, 0 payments outside the mandate, GBP 108 + EUR 80 wrongly sent (it guessed refund amounts when the email had "£60" or "€10" without decimals, and refunded a customer who only asked a question). Written against textbook wording only, not tuned on variants.
D7 Version C is computed, not run. It takes Version B's exact proposals and sends them to a server with every check off, so B and C differ only in the guardrails (same agent decisions, $0 extra). Money is split into "wrong payee, wrong amount or should not be paid" and "right payment, but sent without the required approval", so the second isn't overstated as theft.
D8 Ship B. Three runs each, 25 Oct, Haiku 5.5: B 34/40 right in every run, 0 wrong, 0 outside the mandate, $0.00073 per request, about 4 s. D (orchestrator + specialists) 33/40, 0 wrong, $0.00080 per request, about 5.4 s: one more cautious hand-off (RQ-07) and no gain. A (code) 29/40 with GBP 108 + EUR 80 wrongly sent. C (B's proposals, checks off) put 9 payments outside the mandate in every run.
